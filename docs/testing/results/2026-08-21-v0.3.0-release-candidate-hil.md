## Verdict

The automated real-board release-candidate HIL for commit
`c56b014d2a369c671f16d8a02a23fb1ecb8299b9` is **PASS**. The exact final
combined UF2 was built, flashed, exercised, recovered through both HTTP and CDC

path. These boundaries do not invalidate the automated candidate checks, but
must remain visible in the release decision.

## Findings Corrected During HIL

The first pass exposed two release-blocking contract problems. They were fixed,
the canonical image was rebuilt, and the complete affected hardware paths were
rerun against the exact artifact recorded above.

1. GP29 correctly rejected output mode in firmware but returned generic HTTP
   500 `configure_failed`. HTTP now returns 403 `input_only`, and WebSocket
   returns the same explicit code and explanation. Direct HTTP and WebSocket
   regression checks passed after reflashing the rebuilt candidate.
2. The batch example in the HIL specification used stale `topic=adc` syntax;
   the firmware correctly returned `invalid_topic` because the supported topic
   is `live`. The specification was corrected and the real 4-channel batch run
   passed with zero dropped samples.

Local post-fix validation also passed:

- firmware host-model and offline Python suite, including 87 Python tests;
- workflow contract suite, 69 Node tests;
- nightly-workflow, repository-gate, and test-registration checkers;
- `git diff --check`.
