# 2026-11-06：单路1MHz原始WS持续流核对

此前只验证了单路100kHz，不据此认定当前1MHz失败。本轮在同一授权板
USB`1-7.4.2`／serial`F2836E780B95F053`上执行一个定向用例，未改源码、接线或GPIO方向，
也未新增刺激。现有最终镜像为`adc3618fc7f946b38853539b2d72890b140705448198993c1aeed88462fac850`；
设备没有重启，运行前确认既有PD20／有效5Vout预检状态仍成立。

## 实测

- GP13单路、mask`0x0008`、WS、请求/协商1MHz、pre=0、post=0，客户端在30秒后主动STOP。
- 实际窗口 **30.010686849秒**，收到 **29982720点、1830个DATA帧**。
- overrun、sample-index gap、decode error、disconnect均为0。
- 正常跨越一次24位索引回绕：首样本索引`16760832 → 0`；未将新采集probe的归零算作回绕。
- 收到STOP_RESP，新连接采集探针、HTTP健康及结束后J4ready均通过。
- 全部DATA为codec5（SINGLE_BITS_RLE），输入静态/可压缩；不外推高熵输入、浏览器绘图或无限时长。

## 与“无限流”的区别

当前固件1MHz/post0选择滚动ring，没有100000点总数上限；100/125MHz的特定post0
packed-burst路径是另一种有限行为。Web的Start Stream同样发post0，但缓存只保留最近
1000000样本，到顶丢旧继续收；1MHz约为最近1秒，最大预览窗口262144点。
实时解码单次最多8192点，当前Stream没有持续持久化全部样本的实现。

因此，本次排除了“当前固件原始WS的单路1MHz必然不能持续运行”这一前提，不证明产品页面
端到端性能或任意输入永不丢样。历史单路1MHz高变化率10/10成绩也是各5秒，而非数学意义无限时长。
