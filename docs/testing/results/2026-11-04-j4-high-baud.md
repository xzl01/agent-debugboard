# 2026-11-04：J4 高波特率范围与受限实机验证

## 结论

配置范围已由 4800..115200 扩展为 **4800..3000000 的连续整数**，WebUI 与
CDC ACM 共用此范围，默认仍为 115200。加入 1500000（Rockchip）和 3000000 等
推荐值，共 11 项；推荐值不是白名单，5200、115201 等仍有效。

离线测试及完整构建通过。新 combined UF2 已刷入唯一授权板并正常启动，但
**电源预检失败，后续 UART 配置/收发 HIL 已停止，不能声明 1.5M 或 3M
硬件验收通过。**

## 为什么先前限制在 115200

先前上限来自 `linkr_debugger_serial_model.h` 的产品 policy，而非 UART 位宽或
驱动上限。`apps/pico2_uart_swd_test` 使用通用 interrupt-driven UART bridge，
与正式 J4 同样调用 Zephyr PL011 配置接口，没有 1.5M 专用分频实现。

当前 UART 时钟为 150 MHz，PL011 的 IBRD/FBRD 对 1.5M 为 6/16，对 3M 为 3/8，
两档理论分频均精确。3M 是覆盖 1.5M 需求并留余量的工程候选配置上限，
不是实测可靠上限。保持现有驱动、时钟、GPIO 映射及 CDC DTR ownership，
不为提高范围更换为丢失 multi-sink/CAS/completion 语义的通用 bridge。

旧版高率测试确有失败记录，保留原始历史报告，不把它们改写成此次 PASS。
配置可接受不等于持续满速无损：8N1 下 1.5M/3M 可达 150/300 kB/s，4096 B
ring 只覆盖约 27.3/13.7 ms；UART IRQ 延迟、对端、线路和各 sink 吞吐仍需实测。

## 电源预检：BLOCKED

启动后第一条 host hardware mutation 为 `5v_out=on`，该请求成功；第二条为
fixed PD 20000 mV，返回：

```json
{"schema":"radxa-linkr-debugger.v1","ok":false,"command":"pd",
 "error":{"code":"set_failed","message":"failed to apply PD voltage"}}
```

HTTP 状态为 500。只读检查显示：

- `5v_out` 的使能状态为 on，不能据此声称端口实际有 5 V。
- PD：`available:false`、`voltage_mv:0`、`last_error:-67`、无有效 capabilities。
- INA226：`power_enabled:true`、`voltage_valid:true`、`voltage_uv:0`、
  `current_ua:-250`。不满足启用输出约 5 V 的预检条件。

随后没有自动重放 PD 请求，没有设置其他轨或改 UART line coding，没有发送
目标串口数据。设备保持新固件在线及请求的 5V enable 状态；未更改持久化默认值。
原始只读结果在
`/tmp/opencode/j4-high-baud-2026-11-04/preflight-failure-readonly.json`。

操作者随后确认未接 20 V PD。J4 串口由 USB 供电，不以 PD 或 `5v_out` 供电
作为工作条件；此次停止来自仓库 HIL fixture 的强制预检规程，不能据此推断
串口无法使用，也不能把 PD 缺失解释为 UART 高波特率失败。
