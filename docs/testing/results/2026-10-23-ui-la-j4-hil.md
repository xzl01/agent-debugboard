## J4：真实 resize 与尺寸查询

查询通过真实目标控制台执行：`/usr/bin/resize` → UART 查询 → 浏览器 xterm
自动回复 → 目标 tty 更新，再用 `stty size` 读取。不是向 xterm 注入伪 RX，
也不是只在本地调用 `term.resize()` 后宣布远端通过。

CSI 18t 由目标端 Python 标准库向 `/dev/tty` 发出，再读取真实返回字节；读取
期间保存并恢复 tty 属性，检查完整回复且没有重复尾随回复。

| 场景 | 浏览器行×列 | 目标 `stty size` | 目标收到的 CSI 18t 回复 |
| --- | --- | --- | --- |
| A：初始适配 | 35×168 | `35 168` | `ESC[8;35;168t` |
| B：调整窗口 | 35×126 | `35 126` | `ESC[8;35;126t` |
| C：增大字号 | 35×112 | `35 112` | `ESC[8;35;112t` |
| D：隐藏工作区时更换字体，再显示 | 35×144 | `35 144` | `ESC[8;35;144t` |
| 采集结束后恢复检查 | 27×192 | `27 192` | `ESC[8;27;192t` |

隐藏换字体使用产品的外观设置，选择实际字体族
`"Noto Sans Mono CJK SC", monospace`；隐藏期间终端维持之前的行列和字体，
恢复后应用新字体。实际目标打印的备用屏幕标记 `__HIL_KEEP__` 保留。
窗口 fit 的一个观测区间没有二进制 UART TX，尺寸回复只在目标发起查询后出现。

自动响应由本 QA 页取得的 WS slot 0 提供，DTR 为 false。仅清理本会话创建的
QA 浏览器，没有关闭或删除另一个现存客户端。**本轮未完成完整多客户端/CDC
响应器矩阵**，不能把上述查询结果扩大为所有 responder 切换场景都已验收。

## 连续采样：单路限定通过、五路失败

### GP13 单路

- 100 kHz、mask `0x0008`，约五秒 smoke 取得 **491520 点、30 个 DATA 帧**，
  样本索引无 gap，手动停止收到 STOP response，随后 J4 为 ready。
- 单路使用 SINGLE 优化路径，本轮观测其运行期间 J4 仍为 ready；不能把它
  错当作五路 FAST8 的 UART 暂停行为。
- 单通道选择 I2C 时，页面显示“SDA 和 SCL 不能使用同一个通道”；切换 UART
  后错误消失，仍是同一个波形。此结果验证错误反馈和恢复，不验证有效 I2C 帧。

### GP12–GP16 五路：FAIL

| 观测 | 结果 |
| --- | --- |
| 请求 | 100 kHz、连续模式、mask `0x007c` |
| 提前结束前实际接收 | 325912 点、80 个 DATA 帧 |
| 此前样本索引 gap | 0 |
| 终止事件 | EVENT `OVERRUN`，detail 5，sample index 325912 |
| 事件 payload | `01000518f904` |
| RUNNING 到 OVERRUN 的主机收包时间 | 约 3.523278 s |
| 用户可见反馈 | `Capture overrun`，退出连续采样并清理连接 |

这不是五秒持续采样 PASS，也不是“零 gap 所以通过”。收尾时 J4 已恢复 ready，
采集后真实 `resize` 和 CSI 18t 再次通过，watchdog healthy/armed，没有发生复位。
未在失败后自动重启五路采集，也未继续后端/基准对照；根因仍待定位。

事件汇总见 [continuous-failure.json](2026-10-23-ui-la-j4-hil/continuous-failure.json)。
