# 功率分析仪

基于设备单调时间戳与上位机流式存储的功率分析。功率分析仪捕获电源轨的
电流波形，支持多种触发类型，并且无需把完整记录保存在调试板 RAM 或页面
内存中，可持续记录数小时。

功率分析仪位于 Web UI 右侧工作区的 **电源分析** 页签中，实时采集与启动分析
作为该页签下的两个模式提供。

## 捕获存储

固件只负责检测精确触发点并报告设备时间戳与样本序号，不保存完整波形。样本会
分批实时发送到上位机，
并以紧凑数据块持续写入 IndexedDB。调试板保留 256 点 RAM 环形缓冲，用于吸收
短时传输抖动；一旦缓冲溢出，结果会明确显示 `dropped_samples` 丢样数量，不会
把不完整记录静默当作完整能耗结果，同时禁用电池容量与续航换算。

触发前历史与触发后的数小时记录不同：它必须随时保存在页面内存中，才能在
事件发生时立即回溯。Web UI 因此将触发前历史限制为 60,000 个样本（Web UI
连续记录上限 500 Hz 时为 120 秒）；触发后的样本仍持续写入 IndexedDB，不受该页面内存上限限制。

每个活动归档还会保存由当前浏览器会话持续续期的租约。租约有效时，其他标签页
不会恢复或修改该归档。页面或浏览器确实异常退出后，恢复流程会从 IndexedDB
原始分块重建预览、触发位置、电流/功率摘要、电量和能量，并明确保留“中断”状态。

设定的采样率是请求上限。结果会显示按设备单调时间戳计算的实际平均采样率；
当 ADC 或传输吞吐低于请求值时，能量积分仍按实际时间间隔计算。

## 触发类型

| 触发 | 说明 | 额外参数 |
| --- | --- | --- |
| `manual` | 发送 `capture_trigger` 命令触发 | — |
| `current` | 电流超过阈值时触发 | `threshold_ua`（微安） |
| `power_on` | 电源轨上电事件触发 | — |
| `gpio` | GPIO 边沿触发 | `gpio`（来自安全列表）+ `edge`（`rising`/`falling`/`either`） |

## 启动工作流

捕获生命周期通过现有 live WebSocket 会话的命令完成：

1. **启动**：发送带触发配置的 `capture_arm` 命令
2. **已触发**：固件发送包含设备时间和样本序号的 `capture_triggered`
3. **记录**：上位机把持续收到的 ADC 遥测写入 IndexedDB
4. **停止**：到达设定时长或用户手动停止，上位机发送 `capture_stop`
5. **完成**：上位机完成归档并生成报告

启动命令示例：

```json
{
  "type": "command",
  "command": "capture_arm",
  "id": "capture-1",
  "mode": "host-stream-v1",
  "trigger": "current",
  "output": "5v_out",
  "threshold_ua": 500000,
  "rate_hz": 100
}
```

启动前 Web UI 会确认状态响应包含
`power_capture_protocol: "host-stream-v1"`。如果该字段缺失或版本不同，说明固件与
Web UI 不兼容，页面会在操作硬件前停止并给出错误。

手动捕获在启动后发送 `capture_trigger`。上位机完成记录后发送
`capture_stop`；`capture_cancel` 用于解除触发器。

### 时间戳归一化

用 `capture_triggered.sample_sequence` 匹配遥测中的触发样本，并以该点归一化
X 轴。主机接收时间不是可靠的采样时钟——请使用设备单调时间戳。

## Web UI

### 电源与电流卡片

仪表盘 **电源与电流** 卡片提供：

- 各电源轨的实时电流读数
- 支持手动、电流阈值、GPIO 边沿和上电触发的触发式功率分析
- 最近 4 次捕获的叠加对比
- 导出带设备时间戳的 CSV 或 NDJSON
- 最新捕获的持续时间、mAh 和 Wh 报告（基于设备单调时间戳的梯形积分）
- 支持从数秒到数小时的定时记录，也支持手动停止
- 原始数据持续写入上位机，图表只在内存中保留有界的降采样预览
- 开始定时记录前估算所需空间并保留安全余量；存储空间不足时不会操作调试板
- 二进制分块与归档进度在同一个 IndexedDB 事务内提交；页面异常结束后可保留
  已成功写入的部分记录
- CSV/NDJSON 通过分块游标直接流式写入文件，不会把全部样本和文本同时载入内存
- 存储写入或上位机处理速度跟不上时立即停止记录，并明确显示已接收、已落盘、
  排队和丢失的样本数量

记录期间需要保持 Web 页面和调试板连接。完整原始数据存放在运行浏览器的
上位机中，不写入调试板 Flash。

### 导出格式

| 格式 | 说明 |
| --- | --- |
| CSV | 带设备时间戳的电流/电压样本 |
| NDJSON | 每行一个 JSON 对象，包含设备时间戳 |

两种格式均保留触发配置、源电源轨、边沿/阈值设置、采样率和预/后窗口大小。
大型导出需要支持直接文件流写入的 Chromium 系浏览器；其他浏览器仅允许有大小
上限的内存导出，避免导出本身耗尽页面内存。

## CLI：`adc record`

命令行连续 ADC 录制：

```sh
radxa-linkr-debuggerctl adc record OUTPUT_PATH [MAX_SAMPLES] [--rate-hz HZ]
```

示例：

```sh
# 录制为 NDJSON（默认）
radxa-linkr-debuggerctl adc record /tmp/adc.ndjson 1000 --rate-hz 250

# 录制为 CSV
radxa-linkr-debuggerctl adc record /tmp/adc.csv 1000 --rate-hz 250
```

### 输出详情

- **格式**：默认 NDJSON；输出路径以 `.csv` 结尾时为 CSV
- **设备时间**：保存在 `metadata.device_timing` 下，包含
  `sample_sequence`、`uptime_us` 和 `device_t_mono_us` 字段
- **CSV 时间列**：优先使用 `device_t_mono_us`，回退到 `uptime_us`，最后
  使用 `0`
- **环形溢出**：在受影响的首行报告为 `metadata.dropped_samples`
- **速率**：默认 1000 Hz WebSocket 订阅；`--rate-hz` 接受更低的速率。
  100 Hz 以上的请求使用批量 JSON 传输，录制器将每个设备样本展开为独立行。

## 启动功率分析

位于 Web UI **电源分析** 页签的 **启动分析** 模式中。同时记录上电电流波形和
串口启动里程碑。

### 前置条件

- 已连接的 UART0 或 UART1 串口会话
- 空闲的功率捕获会话

### 工作流

1. 清除并记录目标串口控制台
2. 关闭选定电源轨，等待配置的放电延迟
3. 在恢复电源轨之前启动固件 `power_on` 捕获
4. 上电后独立记录串口接收数据
5. 为上电后的首个 UART 字节、U-Boot/UEFI 标记、内核标记和登录标记
   打时间戳
6. 报告峰值电流、平均功率和积分能量

### 启动固件检测

自动检测从串口输出识别启动固件类型。当目标平台已知时（如 Radxa O6N、
Q6A），可手动指定为 **U-Boot** 或 **UEFI**。

### 结果

- **峰值电流**：使能电源轨上的最大样本值
- **平均功率**：能量除以捕获持续时间
- **积分能量**：基于设备单调时间戳的梯形积分
- **功率曲线叠加**：同一电源轨最近两次完成的运行触发对齐后叠加显示

能量仅覆盖固件捕获窗口，不包含窗口外的串口活动。

### 限制

- 仅保留上电请求后收到的字节；电源轨关闭期间排空的输入视为过期数据
- 无上电后 UART 数据、串口连接丢失或无 Login 签名的捕获报告为部分完成
- `power_on` 捕获将全部捕获容量用于后触发样本；当前固件不返回预触发
  环形缓冲区
- 串口里程碑使用浏览器单调时钟（主机观测时间），功率曲线使用固件
  单调时钟
